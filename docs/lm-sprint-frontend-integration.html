Authentication

Every assessment endpoint requires a valid Supabase JWT in the Authorization header. There are no anonymous endpoints.

typescript — lib/api.ts pattern
import { createClient } from '@/lib/supabase/client'

async function apiRequest<T>(path: string, init?: RequestInit): Promise<T> {
  const supabase = createClient()
  const { data: { session } } = await supabase.auth.getSession()

  if (!session) throw new Error('Not authenticated')

  const res = await fetch(`${process.env.NEXT_PUBLIC_API_URL}${path}`, {
    ...init,
    headers: {
      'Content-Type': 'application/json',
      'Authorization': `Bearer ${session.access_token}`,
      ...init?.headers,
    },
  })

  if (!res.ok) {
    const body = await res.json().catch(() => ({}))
    throw Object.assign(new Error(body.detail ?? res.statusText), { status: res.status })
  }
  return res.json() as Promise<T>
}
Token expiry: Supabase JWTs expire after 1 hour. Always call supabase.auth.getSession() immediately before any API call — it refreshes the token automatically. Never cache the access_token across page navigations.

Story 3-28 — Variable Quiz Counts

The quiz_generator_node now produces tier-aware question batches per segment. No new API endpoint — the change manifests in the LessonPackage already delivered via the generation WebSocket.

LessonPackage Impact

Segment.quiz: QuizQuestion[] was already typed as an array (frozen contract — no change). The difference is that new lessons will have multiple questions per segment:

TierLabelQuestions per segmentPrevious behaviour
T1Full-Depth3–5 questionsAlways exactly 1
T2Standard2–3 questions
T3Refresher1–2 questions

Quiz Submission — Handle Multiple Questions

The submission endpoint accepts an array of answers — all questions for a segment are submitted in a single call. The schema has not changed; only the expected array length changes.

POST /api/assessment/quiz Submit all quiz answers for one segment

Request body

typescript
interface QuizSubmission {
  session_id:  string   // UUID of the active session
  lesson_id:   string   // UUID of the lesson
  segment_id:  string   // segment being quizzed
  answers: QuizAnswer[] // one entry per question shown — min 1, max 50
}

interface QuizAnswer {
  question_id:      string  // exact question_id from LessonPackage
  response_index:   number  // 0-based selected option (must be ≥ 0)
  response_time_ms: number  // ms from question display to selection (default 0)
}

Response body (QuizResult)

typescript
interface QuizResult {
  session_id:       string
  score:            number  // 0.0 – 100.0 (percentage correct)
  correct_count:    number
  total_count:      number
  ces_contribution: number  // 0–35.0 pts — forward to Dev 4 WebSocket signal
  feedback:         Array<{
    question_id: string
    is_correct:  boolean
    explanation: string
  }>
}

Validation rules enforced server-side

  • response_index must be ≥ 0 — negative values return HTTP 422
  • response_time_ms must be ≥ 0 — negative values return HTTP 422
  • answers array: min 1, max 50 — empty array returns HTTP 422
  • Unknown question_id returns HTTP 422 (detail does NOT expose valid ID list)
  • Session must belong to the authenticated user — mismatch returns HTTP 403

Frontend implementation

typescript — quiz player pattern
// Collect all answers for a segment and submit in one shot
async function submitSegmentQuiz(
  sessionId: string,
  lessonId: string,
  segment: Segment,
  selectedIndices: Map<string, number>,    // questionId → selectedIndex
  responseTimes: Map<string, number>,      // questionId → ms
) {
  const answers = segment.quiz.map(q => ({
    question_id:      q.question_id,
    response_index:   selectedIndices.get(q.question_id) ?? 0,
    response_time_ms: responseTimes.get(q.question_id) ?? 0,
  }))

  return apiRequest<QuizResult>('/assessment/quiz', {
    method: 'POST',
    body: JSON.stringify({ session_id: sessionId, lesson_id: lessonId,
                           segment_id: segment.segment_id, answers }),
  })
}
CES wiring: Pass QuizResult.ces_contribution to Dev 4's attention signal via WebSocket. Do not multiply by 100 again — the value is already on the 0–35.0 point scale.

New Field — Story 3-30: Learner DNA Snapshot

learner_dna_snapshot : LearnerDnaSnapshot | nullNEW 3-30
Present when the user has a learner_dna row (i.e., completed onboarding). null for first-session users who have not yet completed onboarding.

Contains two sub-maps, both keyed on the same 9 dimension names:
  • dimension_labels — current descriptive label per dimension (never raw floats)
  • growth_labels — directional change in this session (or null if no prior session)
typescript — LearnerDnaSnapshot shape
type DimensionName =
  | 'pattern_recognition'
  | 'logical_deduction'
  | 'processing_speed'
  | 'frustration_tolerance'
  | 'persistence'
  | 'help_seeking'
  | 'goal_orientation'
  | 'curiosity_index'
  | 'study_independence'

type DimensionLabel = 'Beginning' | 'Developing' | 'Proficient' | 'Advanced'
type GrowthLabel    = 'Improving' | 'Stable' | 'Declining' | null

interface LearnerDnaSnapshot {
  dimension_labels: Record<DimensionName, DimensionLabel>
  growth_labels:    Record<DimensionName, GrowthLabel>
}

LabelUnderlying score rangeDisplay meaning
Beginning0 – 25Early-stage — encourage, not alarm
Developing25 – 50Building foundations

Growth label values (growth_labels)

ValueMeaningDisplay suggestion

Do not display raw dimension scores to students. The backend never returns numeric floats via learner_dna_snapshot — only descriptive labels. If you need to show "progress" use only dimension_labels and growth_labels. This is a DPDP Act 2023 compliance requirement (CLAUDE.md).

Loading and retry behaviour

1

Show skeleton immediately

Display a report skeleton on navigation. The API has 6 DB calls — expect 300–800 ms latency on cold Supabase connections.

2

Retry once on 5xx

Retry the report fetch once after 2 seconds on HTTP 500/503. Do not retry on 404 (session not found — navigate to dashboard instead).

3

Handle null DNA snapshot gracefully

learner_dna_snapshot is null for first-session users. Render the DNA section only if the value is non-null.

Story 3-31 — Re-Assessment Prompt After 10 Sessions

After every 10th completed session, the backend sets a Redis flag (user:{id}:reassessment_due = "1"). The frontend must check this flag via the DNA endpoint and prompt the student to redo the 20-question diagnostic.

GET /api/assessment/user/dna — New Field

GET /api/assessment/user/dna Current user's Learner DNA profile

This endpoint existed before the LM sprint. Story 3-31 adds one field: reassessment_due.

typescript — LearnerDNA response (updated)
interface LearnerDNA {
  user_id:           string
  badge_labels:      string[]      // e.g. ['Pattern Thinker', 'Self-Starter']
  profile_text:      string | null // descriptive profile + DPDP disclaimer
  session_count:     number        // total sessions completed (EMA blended)
  last_updated:      string | null // ISO 8601 datetime
  reassessment_due:  boolean       // ← NEW in Story 3-31
  // true every 10th session (10, 20, 30, …) until the diagnostic is re-submitted
}

When is reassessment_due true?

  • Set to true when session_count reaches a multiple of 10 (10, 20, 30, …)
  • Set by fuse_learner_dna() immediately after the 10th session ends
  • Persists as true until the student re-submits the onboarding diagnostic
  • Returns false when Redis is unavailable (safe default — no false positives)

Onboarding Re-Submission

The POST /api/assessment/onboarding/submit endpoint handles both first-time submission and re-assessment re-submission transparently. The frontend code path is identical — the backend detects the reassessment_due flag and clears the idempotency lock automatically.

POST /api/assessment/onboarding/submit First-time or re-assessment diagnostic submission
typescript — request body
interface OnboardingDiagnosticSubmission {
  responses: OnboardingAnswer[]  // exactly 20 answers (min_length=20, max_length=20)
}

interface OnboardingAnswer {
  question_id:     string
  dimension:       'cognitive' | 'emotional' | 'self_direction'
  selected_index:  number       // 0–3 (Pydantic: ge=0, le=3)
  selected_text:   string
  response_time_ms?: number     // optional; ≥ 0 if provided
}
typescript — response body (201 Created)
interface OnboardingResult {
  badge_labels:  string[]       // e.g. ['Pattern Thinker', 'Self-Starter']
  profile_text:  string         // descriptive profile + DPDP Act 2023 disclaimer
  session_count: number         // always 0 for first-time; carries over for re-assessment
}

Error handling for onboarding submit

HTTP statusWhenFrontend action

First-time vs re-assessment: Both use the same frontend form and the same API call. The difference is invisible to the frontend — the backend handles idempotency internally. When reassessment_due is true, the backend unlocks the form automatically before the student submits.

Common Pitfalls

Pitfall 1: Assuming quiz.length === 1. Any hardcoded check like if (segment.quiz.length === 1) or accessing segment.quiz[0] directly without guard will break on T1/T2 lessons. Always iterate segment.quiz.
Pitfall 2: Displaying quiz_score to the student. quiz_score is a raw float (0–100) retained for Dev 4's CES computation. Show quiz_accuracy_label ("Strong", "Developing", "Needs Review") instead. DPDP compliance requirement.
Pitfall 3: Showing raw DNA dimension numbers. The snapshot gives you dimension_labels (strings). Never expose the underlying 0–100 floats; they're not in the response shape at all — but don't add them. CLAUDE.md Learner DNA display rules.
Pitfall 4: Blocking on reassessment_due. The prompt must be dismissible. Never block lesson playback or navigation because re-assessment is due — students choose when to take it.
Pitfall 5: Caching JWT across navigations. Supabase tokens expire after 1 hour. Always call supabase.auth.getSession() inline before API calls — it auto-refreshes. Stale tokens will get 401 with no useful error shown.
Pitfall 6: Dismissing reassessment_due based on boolean alone. Store the dismiss state keyed on session_count (not just a single boolean in localStorage). Otherwise dismissing at session 10 silently suppresses the prompt at session 20.
Note: DNA snapshot null for new users. learner_dna_snapshot is null when the user has no learner_dna row (before onboarding). Render the DNA section conditionally — report.learner_dna_snapshot !== null — to avoid null-pointer errors.
Note: growth_labels can be null per-dimension. First-session users (or dimensions with no prior data) will have null growth labels. Render a dash or no growth indicator — not "Stable" — for null values.
Note: tier defaults to T2 when lessons row is missing. If a session references a lesson that no longer has a lessons row, the backend returns tier="T2" and tier_label="Standard" silently. The frontend will always receive a valid, non-null tier.
Note: DB migration is a blocker for tier display. If 20260714020000_add_lesson_tier.sql hasn't been applied, lessons.tier doesn't exist and the backend degrades to T2 default for every session. Verify with Dev 1 that the migration is applied before demoing tier-contextualised reports.
