Top-Line Verdict

Vexyl TTS is real but is not a hosted cloud API. It is a free, open-source, self-hosted server wrapping the ai4bharat/indic-parler-tts model. It has 41 GitHub stars, zero Product Hunt listing, zero Reddit/HackerNews presence, and all discoverable content traces back to its solo creator or one promotional blog post. It does not return word-level timestamps. Uncached CPU latency runs 2–7 seconds per sentence — unsuitable for a real-time lesson audio-timeline state machine. TransformED's existing Sarvam → Azure → Browser fallback chain is the correct architecture.

1. What Vexyl TTS Actually Is

Vexyl TTS (github.com/vexyl-ai/vexyl-tts) is an open-source, self-hosted TTS server maintained by a single developer (Anil Mathew / Vexyl AI). It wraps ai4bharat/indic-parler-tts — a community Indian-language TTS model — and exposes it via WebSocket and REST APIs. It is not a commercial SaaS API. There is no hosted endpoint, no per-character billing, and no docs.vexyl.ai or api.vexyl.ai (both return connection refused).

Flag: The broader Vexyl AI commercial product (vexyl.ai) is a telephony/voice-bot platform for Asterisk/FreePBX. It uses other providers' TTS (including Sarvam) via BYOK — it does not ship its own synthesis endpoint. The open-source TTS server and the commercial calling platform share a brand but are separate products.

2. Word-Level Timestamps / Timing Data

Answer: No. Vexyl TTS does not return word-level timestamps, phoneme timing, or any audio-text alignment data. The response payload contains only a base64-encoded WAV blob and a latency_ms field (inference monitoring only, not playback timing). This is an architectural limitation of the underlying indic-parler-tts model, which does not expose forced-alignment output.

If the TransformED lesson player needs word-boundary events for subtitle highlighting or audio-timeline sync, Azure TTS is the only provider in the current stack with confirmed word-level timestamp support (via SSML <bookmark> elements and WordBoundary SDK events). Sarvam Bulbul v2 has no documented timestamp capability.

3. Actual API Response Format

WebSocket (real-time) — primary interface

Server → Client on connect:

{
  "type": "ready",
  "model": "indic-parler-tts",
  "sample_rate": 22050
}

Client → Server (synthesis request):

{
  "type": "synthesize",
  "text": "नमस्ते दुनिया",
  "lang": "hi-IN",
  "style": "default",
  "request_id": "1"
}

Server → Client (audio response):

{
  "type": "audio",
  "request_id": "1",
  "audio_b64": "<base64-WAV>",
  "sample_rate": 44100,
  "cached": false,
  "latency_ms": 2400
}

Additional server message types: stats, pong, error.

REST Batch API

POST /batch/synthesize → Response (202 Accepted):

{
  "job_id": "batch_a1b2c3d4",
  "status": "queued",
  "language": "hi-IN",
  "style": "default",
  "text_length": 14
}

GET /batch/status/{job_id} → Response when complete (200 OK):

{
  "job_id": "batch_a1b2c3d4",
  "status": "completed",
  "audio_b64": "...",
  "latency_ms": 2400
}

8. Implications for TransformED

The existing TTS fallback chain (Sarvam Bulbul v2 → Azure TTS → Browser Speech) is correct and does not need Vexyl TTS.
  • Vexyl is not a drop-in hosted API. It requires deploying and maintaining a server with 4–6 GB RAM and optionally a GPU. That is infrastructure overhead for a team already managing Railway + Redis + Supabase.
  • Latency is incompatible with real-time narration. At ~2.85s per 100-char sentence (GPU, uncached), it cannot sustain the lesson audio-timeline state machine. The $3.00/lesson ceiling also means a GPU server must be fully amortised across enough lessons to justify it.
  • No word-level timestamps — if the player ever needs audio-text sync highlighting, Azure TTS is the only option in the current stack.
  • Sarvam Bulbul v2 is superior for Indian language quality (MOS 4.6 Hindi / 4.4 Tamil, sub-200ms TTFB from India-region infra), and the creator of Vexyl AI explicitly uses Sarvam in their own commercial telephony product.
  • Community signal is very thin. 41 GitHub stars, zero Reddit/HN/Product Hunt presence, and all external content is creator-authored. This is not a disqualifying signal for open-source tooling, but it does mean limited community support and unknown production hardening.
