Fish Audio TTS API — Technical Research Report

Researched 2026-09-03  |  Sources: docs.fish.audio, fish.audio, 3rd-party docs, GitHub
Context: This report evaluates Fish Audio as a potential TTS provider for the TransformED platform (replacing or supplementing Sarvam Bulbul v2 → Azure → Browser Speech fallback chain). Key question is whether it can provide word-level timing for audio-timeline synchronization in the lesson player.

1. Word-Level Timestamps / Alignment Data VERIFIED

YES — Fish Audio has a dedicated streaming endpoint that returns segment-level timestamp data.

The Endpoint

POST https://api.fish.audio/v1/tts/stream/with-timestamp

Returns a Server-Sent Events stream where each event carries a JSON payload:

{
  "audio_base64": "string",      // base64 chunk of audio
  "content": "string",           // text content of this chunk
  "chunk_seq": 1,                // sequence number
  "chunk_audio_offset_sec": 0.0, // global offset for this chunk
  "alignment": {
    "segments": [
      { "text": "Hello", "start": 0.0, "end": 0.35 },
      { "text": "world", "start": 0.35, "end": 0.72 }
    ],
    "audio_duration": 0.72
  } // null before first snapshot or when unavailable
}

Critical Details

  • Timestamps are segment-level, not word-level. The "segments" array corresponds to text segments chunked by the chunk_length parameter — typically phrases/sentences, not individual words.
  • Segment times are relative to chunk start. Add chunk_audio_offset_sec to get absolute timeline position.
  • alignment replaces (not appends) the previous snapshot for the same chunk_seq — store in a map keyed by chunk_seq.
  • The standard TTS endpoint (/v1/tts) returns raw binary audio only — no timing data whatsoever.
  • No phoneme-level timing output. Phoneme control (CMU Arpabet etc.) is input-only — it tells the model how to pronounce, does not return timestamps.
  • No forced-alignment endpoint. No separate endpoint to align pre-existing audio to text.

Phoneme INPUT Control (not output)

Fish Audio accepts phoneme-level pronunciation hints via inline tags in the request text. This is input control only — it does NOT return phoneme timestamps.

// English (CMU Arpabet)
"I am an <|phoneme_start|>EH1 N JH AH0 N IH1 R<|phoneme_end|>."

// Chinese (tone-number pinyin)
"我是<|phoneme_start|>gong1<|phoneme_end|><|phoneme_start|>cheng2<|phoneme_end|>"

Supported for: English (CMU Arpabet), Chinese (Pinyin), Japanese (OpenJTalk romaji). Hindi and Indian scripts: not documented for phoneme control.

Sources: docs.fish.audio/api-reference/endpoint/openapi-v1/text-to-speech-stream-with-timestamps | docs.fish.audio — fine-grained-control

4. SSML / Structured Timing Output NOT SUPPORTED

Fish Audio does NOT support SSML. They use a custom inline tag syntax instead.

Their Alternative: Inline Bracket Tags

Place natural-language emotion/delivery instructions directly in text using square brackets:

[whispering] I didn't want to go inside.
I didn't want to [emphasis] really mean it.
[angry] How dare you!

Supported Tag Categories (S2-Pro / S2.1-Pro)

  • Emotion: [angry], [sad], [excited], [embarrassed]
  • Voice style: [whispering], [soft], [breathy], [shouting]
  • Pacing: [pause], [long pause]
  • Vocal sounds: [laughing], [chuckling], [sobbing], [sighing], [panting], [clear throat]
  • Open-domain: Any natural-language description accepted — "whispers sweetly", "says nervously"

S1 Model (Legacy)

S1 uses parenthesis syntax instead: (angry), (laughing) etc. — 64+ predefined expressions.

Paralanguage Controls

Special parenthesis tokens for non-verbal sounds: (break), (long-break), (breath), (laugh), (cough), (lip-smacking), (sigh)

Sources: fish.audio blog — S2 word-level control | docs.fish.audio — fine-grained-control

5. Forced-Alignment Endpoint NOT FOUND

No forced-alignment endpoint exists in Fish Audio's documented API surface.

Fish Audio offers:

  • TTS with inline timestamps — generates audio AND returns segment offsets simultaneously
  • Speech-to-Text (ASR) — transcribes audio with segment-level timestamps (see Q1 above for STT details)

There is no "give me existing audio + transcript, return aligned timestamps" endpoint. If forced alignment is required, an external tool (WhisperX, Montreal Forced Aligner, etc.) would be needed.

Latency Mode Parameter

The latency field on TTS requests accepts:

  • "low" — lowest TTFA, may trade quality
  • "balanced" — ~300ms TTFA, good for interactive apps (docs call this recommended for voice agents)
  • "normal" (default) — most stable output, slightly higher latency

TTFA Benchmarks (from Fish Audio blog)

  • S2.1-Pro: ~70ms TTFA at single request on production infrastructure
  • S2-Pro: ~100ms TTFA (documented in models overview)
  • Streaming first chunk: 80–150ms (blog claim, varies by region/load)
  • "Under 200ms on a normal connection" for streaming audio start
CAUTION: Fish Audio's blog self-reports these numbers. No independent benchmark data found. Actual latency from India (Railway is US-hosted) will be higher. Fish Audio doesn't have confirmed India-region infrastructure.

chunk_length Parameter (Latency Tuning)

Controls text batching before generation: range 100–300 (default 300, but some docs say 200). Smaller values → lower TTFA but less efficient. The min_chunk_length parameter (0–100, default 50) sets a minimum batch size floor.
