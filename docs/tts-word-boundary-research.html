Azure Cognitive Services TTS — Full Technical Detail

1. Mechanism: SDK-Streamed Events (primary path)

Word boundary data is delivered via SDK event callbacks, not via the standard real-time REST API HTTP response body. The REST endpoint at /cognitiveservices/v1 returns raw audio bytes only — no timing metadata is in the HTTP response. Microsoft's own documentation states:

"Use cases for the text to speech REST API are limited. Use it only in cases where you can't use the Speech SDK. For example, with the Speech SDK you can subscribe to events for more insights about the text to speech processing and results."
— learn.microsoft.com/azure/ai-services/speech-service/rest-text-to-speech

The SDK event is called WordBoundary (C#/.NET), synthesis_word_boundary (Python), and wordBoundary (JavaScript). It fires before the corresponding word is played — in real time as audio chunks arrive from the service.

2. Exact SDK Event Properties

Confirmed from the official .NET, Python, and JavaScript SDK reference pages. The event arguments class is SpeechSynthesisWordBoundaryEventArgs.

Property name (Python) Property name (C#) Property name (JS) Type Unit Description SDK version added
audio_offset AudioOffset audioOffset int / uint64 Ticks (100 ns) Elapsed audio time from start of synthesis to start of this word 1.7.0
duration Duration duration TimeSpan / int Ticks (100 ns) Audio duration of the word 1.21.0
text Text text string — The word text that triggered this event 1.21.0
text_offset TextOffset textOffset int Characters Character position in input text immediately before this word 1.7.0
word_length WordLength wordLength int Characters Character length of the word in input text 1.7.0
boundary_type BoundaryType boundaryType enum — Word, Punctuation, or Sentence 1.21.0
result_id ResultId — string — Unique synthesis result ID 1.25.0
Unit conversion required: Both audio_offset and duration are in ticks (100 nanoseconds). To convert to milliseconds: divide by 10,000. The official Python sample uses (evt.audio_offset + 5000) / 10000 to convert with rounding.

3. How to Subscribe (Python, C#, JS examples)

# Python
def word_boundary_cb(evt):
    print(f"Word: '{evt.text}'")
    print(f"  AudioOffset: {(evt.audio_offset + 5000) / 10000:.1f} ms")
    print(f"  Duration:    {evt.duration.total_seconds() * 1000:.1f} ms")
    print(f"  TextOffset:  {evt.text_offset} chars")
    print(f"  WordLength:  {evt.word_length} chars")
    print(f"  BoundaryType: {evt.boundary_type}")

synthesizer.synthesis_word_boundary.connect(word_boundary_cb)
// C#
synthesizer.WordBoundary += (s, e) => {
    Console.WriteLine($"Word: \"{e.Text}\"");
    Console.WriteLine($"  AudioOffset: {(e.AudioOffset + 5000) / 10000} ms");
    Console.WriteLine($"  Duration:    {e.Duration.TotalMilliseconds} ms");
    Console.WriteLine($"  BoundaryType: {e.BoundaryType}");
};
// JavaScript
synthesizer.wordBoundary = (s, e) => {
    console.log(`Word: "${e.text}"`);
    console.log(`  audioOffset: ${(e.audioOffset + 5000) / 10000} ms`);
    console.log(`  duration: ${e.duration / 10000} ms`);   // ticks → ms
    console.log(`  boundaryType: ${e.boundaryType}`);
};

4. Enabling Sentence-Level Boundaries

By default, WordBoundary fires on words and punctuation. To additionally receive sentence-level events, set this SDK property:

# Python
speech_config.set_property(
    property_id=speechsdk.PropertyId.SpeechServiceResponse_RequestSentenceBoundary,
    value='true'
)

5. Viseme Events (lip-sync)

A separate VisemeReceived event is also available in the SDK. It fires with each phoneme transition and is intended for animating a character's mouth/face. This is distinct from the WordBoundary event.

6. Alternative: Batch Synthesis REST API + wordBoundaryEnabled

The Batch Synthesis API (asynchronous, not real-time) is the one REST-accessible path that produces word timing data. When "wordBoundaryEnabled": true is set in the job request, the results ZIP includes a [nnnn].word.json file.

Important difference from SDK: The .word.json file uses milliseconds — not ticks. The SDK uses ticks.
FieldTypeUnitDescription

AudioOffsetnumberMillisecondsStart of word relative to audio start

Example 0001.word.json output (directly from official Microsoft docs):

[
  { "Text": "The",     "AudioOffset": 50,   "Duration": 137 },
  { "Text": "rainbow", "AudioOffset": 200,  "Duration": 350 },
  { "Text": "has",     "AudioOffset": 562,  "Duration": 175 },
  { "Text": "seven",   "AudioOffset": 750,  "Duration": 300 },
  { "Text": "colors",  "AudioOffset": 1062, "Duration": 625 },
  { "Text": ".",        "AudioOffset": 1700, "Duration": 100 }
]
Batch API is NOT real-time. P50 latency is 10–20 seconds; P95 is 120 seconds. This path is unsuitable for TransformED's per-segment narration pipeline. It is documented here for completeness only.

8. Known Reliability Caveat

A tracked GitHub issue on azure-sdk-for-python (issue #39683) documents that WordBoundary events are sometimes not triggered at all, particularly in multithreaded scenarios. This is a known SDK bug, not a design limitation. Events firing before corresponding audio is heard is the intended behavior; the caller must synchronize streaming with real-time playback.

Sarvam AI Bulbul v2 — Full Technical Detail

1. Does Bulbul v2 Return Timing Data?

No. The Sarvam TTS REST API returns exactly two fields:

FieldTypeDescription
request_idstringUnique identifier for the API request
audiosarray of stringsBase64-encoded audio file(s); one element per input text chunk

Example response (from official Sarvam API reference):

{
  "request_id": "20241115_12345678-1234-5678-1234-567812345678",
  "audios": [
    "UklGRiQAAABXQVZFZm10IBAAAAABAAEAQB8AAAB9AAACABAAZGF0YQAAAAA..."
  ]
}

There is no phoneme, word-level, sentence-level, or any other alignment/timing field. No streaming event system exists in the Sarvam TTS API. No documentation or community discussion found indicating this is planned.

2. Audio Formats Supported

Bulbul v2 (and v3) support the following audio encoding formats (set via request parameter):

  • WAV
  • MP3
  • Linear16 (PCM)
  • Mulaw
  • Alaw
  • Opus
  • FLAC
  • AAC

4. Community / GitHub Evidence

A search across GitHub, Dev.to, and developer community discussions (2025–2026) found no evidence of:

  • Any Sarvam TTS word alignment or timestamp feature
  • Any roadmap or issue tracker entry requesting/planning such a feature
  • Any unofficial workaround or third-party wrapper providing timing data

Third-party integrations (LiveKit, Pipecat, Mastra) all consume only the raw audio from audios[0]. None attempt to extract or use timing data.

Implications for TransformED

TransformED's TTS fallback chain is Sarvam Bulbul v2 → Azure TTS → Browser Speech. Given this comparison:

  • Word-synchronised karaoke / subtitle highlighting during lesson playback is only possible when Azure TTS is the active provider. It is not possible when Sarvam is the primary provider, because Sarvam returns no timing data.
  • Any React audio-timeline feature that depends on per-word timing must degrade gracefully when Sarvam is used — either no highlighting, or a time-estimated fallback based on audio duration and word count.
  • Azure SDK integration (not REST) is required to get word boundaries in real-time. The /cognitiveservices/v1 REST endpoint returns audio bytes only.
  • If word-boundary sync is a product requirement, it drives preference for Azure TTS as the primary provider (rather than the fallback), with Sarvam used only where Indic language fidelity is the priority and sync is explicitly degraded.
  • Vexyl / Fish Audio comparison: whether those providers beat one or both of these two on timing depends on their documented feature sets — but the data above establishes the baseline: Azure has rich, real-time timing data; Sarvam has none.
