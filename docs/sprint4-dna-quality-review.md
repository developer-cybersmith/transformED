## 1. Purpose

Automated quality gate to confirm `learner_dna.profile_text` values are free of
clinical language, raw numeric scores, missing DPDP disclaimers, discouraging tone,
and non-plain badge labels before real-student launch.

---

## 2. Checklist Rules

| Rule | Description | Pattern / Substring |
|------|-------------|---------------------|
| `no_clinical` | No IQ / EQ / SQ / clinical / disorder language | `\b(iq\|eq\|sq\|clinical\|diagnos\w*\|disorder)\b` (case-insensitive) |
| `no_raw_scores` | No numeric score patterns in profile text | `\d+/\d+` or `score:\s*\d` |
| `has_dpdp` | DPDP Act 2023 disclaimer present | Substring: `"DPDP Act 2023"` |
| `encouraging_tone` | No discouraging language | `\b(struggle\|fail\w*\|weak\|poor)\b` (case-insensitive) |
| `plain_badge_labels` | Badge labels contain no colon (no "IQ: High" style) | `:` in any badge string |

## 5. Prompt Fixes Required

Based on the fixture violations, the LLM system prompt for `learner_dna` generation
(in `modules/assessment/`) must:

1. **no_clinical** — Explicitly forbid IQ, EQ, SQ, "clinical", "disorder", "diagnos*" in system prompt.
2. **no_raw_scores** — Instruct model to describe performance in qualitative terms only
   (e.g., "strong recall" not "score: 87").
3. **has_dpdp** — Append the DPDP disclaimer as a *required suffix* instruction:
   `"Always end with: This profile is generated by AI and is not a clinical assessment. Data processed per DPDP Act 2023."`
4. **encouraging_tone** — Add: "Use an encouraging, growth-focused tone. Avoid words
   like struggle, fail, weak, or poor."
5. **plain_badge_labels** — Specify: "Badge labels must be 1-3 plain English words with
   no colons or numeric values. Examples: 'Pattern Thinker', 'Visual Learner'."

These prompt constraints are for the LLM node that writes `learner_dna.profile_text`
and `badge_labels`. Implementation is a Dev 3 prompt-engineering task, tracked
separately.
